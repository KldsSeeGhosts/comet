A successful send confirms dispatch or queue admission, not turn completion.
--wait-until-idle waits for target availability before dispatch. To collect a
result, send, then run agent wait --idle and agent read. Provider turn failures
are returned as target errors; subscribe emits a target_error and stops.

run accepts 1-8 labeled roles and launches them in parallel as separate tabs.
Each role must finish with `sc team report`. Results are delivered to a
registered launching agent; other CLI callers receive a completion notification
and can read results with `sc team status --run ID`. Report summaries are
capped at 16 KiB; use --result-file for detailed output. Status and list are
read-only. Cancel leaves a run active if any working role does not confirm it
stopped. After an app restart, every previously nonterminal run is Interrupted
and is not resumed automatically.
For strict sequencing (A finishes, then B starts), wait
with `sc agent wait --to label:A --idle` between launches instead.

list prints workspaces in sidebar order: sections, project groups, worktree
rows (resolved sidebar title, status, local Git position, diff, PR), and nested agent-session rows
with context usage where known. Shared Context rows include shared_context
metadata: group rows and materialized child repositories with parent_worktree
and their project icon. Child worktree names retain their canonical group::repo identity.
watch streams JSONL events: an initial snapshot plus revisioned deltas.
Opens the super.engineering workspace containing PATH. A linked Git worktree of
a known project stays in that project's existing workspace; an unknown project
root creates a new app workspace.
select changes the in-app workspace selection; --activate also foregrounds the app.
create supports individual, Shared Context, and remote workspaces; get --json
returns type-specific configuration and theme overrides; update changes common
name/icon metadata; add mutates type-specific contents in the background; theme
changes per-workspace colors; move changes sidebar order; delete requires --confirm
and uses the UI cleanup lifecycle.

For api_chat rows, stable_id: null means no live view (parked or lazily restored),
not a deleted conversation. Agent stable_target_id values survive parking.
